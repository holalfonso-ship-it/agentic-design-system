# Métrica de adopción agéntica

Esta página no mide cuánta gente usa Aida: mide si los **agentes que la
consultan siguen el protocolo de `CLAUDE.md`** en vez de inventar
componentes o forzar uno que no encaja. Es el dato que sostiene el
argumento de fondo del proyecto — que un design system se puede
estructurar para que un agente lo use bien, no solo para que una persona
lo lea.

Los números se generan con `npm run adoption-report` (`scripts/adoption-report.mjs`),
leyendo directamente `flags.jsonl`, el historial de git y la metadata de
cada componente — nunca a mano. Última vez generado: <code>{new Date(report.generatedAt).toLocaleString("es-ES")}</code>.

## Qué significa cada indicador

<div className="aida-boxed-list aida-boxed-list--dot">

- **flags.jsonl** (`{report.flags.flagged}` flagged, `{report.flags.resolved}` resolved): la puerta de salida legítima de la regla "cuando nada encaja" (`CLAUDE.md`). Muchos `resolved` sin acumular `flagged` sin cerrar es la señal sana; un flag abierto durante varios Ciclos ARC sin resolver es la señal a escalar.
- **Crear vs. extender**: de los commits `feat:` que tocan `src/components`, cuántos añaden el primer `.tsx` de un componente nuevo frente a cuántos modifican uno que ya existía. Es aproximado por diseño — un commit `feat:` de herramientas (p. ej. Storybook) no toca ningún `.tsx` de componente y no cuenta en ninguno de los dos lados.
- **Cobertura de metadata**: `guidelines` (do's y don'ts, obligatorio desde el 2026-10-14) y `figma.componentKey` deberían tender al 100%; `constraints` es opcional (2026-10-21) y solo lo lleva un componente con un límite estructural real, así que un número bajo aquí no es un problema — lo sería que subiera sin que haya un caso real detrás.
- **Drift por Ciclo ARC**: hallazgos (`hallazgos`) vs. cerrados (`cerrados`) de cada Audit → Report → Compose, leído de `src/adoption/arc-cycles.json` (seed manual desde Notion — "🔁 Ciclos ARC — Aida"; no hay forma de leer Notion en un build estático de Storybook, así que esa tabla se actualiza a mano tras cada Audit nuevo).

</div>
